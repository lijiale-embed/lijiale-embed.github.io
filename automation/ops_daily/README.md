# 电商运营日报自动化与库存预警

业务痛点：运营需要合并订单、商品、退款和库存，手工去重与求和容易遗漏冲突与异常。
本项目是个人模拟业务练习。环境安装与整体运行命令见上级 README。

## 实现

1. pandas 读取 orders*.csv / orders*.xlsx，商品主数据 products.xlsx，退款 refunds.csv。
2. order_id 完全相同记录去重；内容冲突的同号订单全部进入异常，避免取首行掩盖冲突。
3. 校验 SKU、数量、日期、状态与金额；金额以分核算，拒绝负数、NaN、无限值、三位小数。
4. 限定当日 paid 订单，销售额为 qty × unit_price。cancelled 和非当日订单不计销售。
5. refund_id 去重，success 且能对应当日有效订单才计退款；累计退款超出订单金额时整组转异常。
6. 库存小于等于阈值时预警。销量为退款前售出件数，退款按金额核算，不虚构退货件数。
7. openpyxl 输出日报汇总、商品销量、库存预警、异常清单，配合日志及状态文件。

## 实际运行

`python ops_daily/pipeline.py --date 2026-10-15`，可通过 --input、--output 指定路径。
固定样例：17 行订单，6 个有效订单，销售额 1500 元、退款 197 元、退款后销售额 1303 元。
3 个低库存商品、12 条异常。11/11 项预设指标一致。实测耗时见 outputs/metrics.json。
pytest 包含异常标识核对、重复执行、缺列失败、商品主数据重复与边界值测试。

## 文件

data：虚构输入与 expected.json 独立验收答案。
outputs/运营日报.xlsx：实际生成的结果值报表，源数据变更后需重跑。
outputs/exceptions.json：逐条异常及原因；run.log：过程日志；metrics.json：本次状态与耗时。
report-preview.html 及作品集截图展示实际 XLSX 的单元格值，不冒充 Excel 软件界面。

统计口径不覆盖历史订单跨日报退款；真实业务需要按业务日、订单日及退款日重新确认归属。
